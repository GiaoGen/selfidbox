# RLS Audit Findings (2026-06-24)

## Critical: Status Mismatch
- Migration 013 uses `'submitting'` in RLS policies but migration 005 CHECK constraint only allows `'submitted'`
- Tables affected: `quizzes`, `quiz_factors`, `quiz_results`, `quiz_questions`, `quiz_options`
- Impact: ANY `submitted` quiz is invisible to public — only creator can see them via creator-owned policy
- Fix: Align both to use same status value

## Policy Gaps
- `quizzes` INSERT: no status restriction (users could insert with `status='published'` via anon key)
- `quizzes` UPDATE: no explicit WITH CHECK clause (relies on implicit PostgreSQL default)
- `quiz_attempt_answers` INSERT: no `quiz_id` consistency check with parent `quiz_attempts.quiz_id`
- `test_site_clicks` INSERT: `check(true)` — unauthenticated spam vector (though app uses service_role for actual clicks)
- Storage `quiz-result-images` INSERT: only checks `bucket_id`, no per-user folder isolation, no DELETE policy

## search_path Inconsistency
- `ensure_user_credits` RPC uses `SET search_path = 'public'` while sibling RPCs (`spend_credit`, `grant_credit`) use `SET search_path = ''` with fully qualified names

## Outdated Documentation
- `supabase/rls-policies.sql` line 167 says admin uses anon key — actually uses service_role
